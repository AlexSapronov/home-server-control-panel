# Мониторинг OpenWrt

Версия 0.2 читает состояние AdGuard Home, zapret и tg-ws-proxy через ограниченный SSH-ключ. Токен Proxmox, пароль панели и секрет Telegram-прокси не передаются на роутер и не выводятся в телеметрию.

## Что проверяется

| Показатель | Источник | Ограничение |
| --- | --- | --- |
| AdGuard / Telegram | `ubus service list`, только `running` | Процесс может работать с ошибками |
| zapret | procd; если записи нет — наличие `nfqws`, `nfqws2` или `tpws` в `/proc/*/comm` | Не проверяет правила и фактический обход DPI |
| DNS | UDP-запрос A `example.com` из контейнера на порт 53 роутера | Не измеряет блокировку рекламы и не гарантирует доступность всех DNS-имён |
| Порты AdGuard / Telegram | TCP-подключение из контейнера; по умолчанию 3001 / 1443 | Не проверяет авторизацию или работу протокола Telegram |
| WAN | `ubus network.interface.wan status` | Состояние интерфейса не является проверкой интернета |
| AmneziaWG | `awg show interfaces`, `latest-handshakes`, список интерфейсов netifd | Поднятый интерфейс не означает рабочий маршрут; handshake может отсутствовать |

Процессы не запрашиваются через `ps` с аргументами: команда Telegram-прокси может содержать секрет. Сборщик выбирает только разрешённые поля из ubus, не выдаёт командные строки или ключи VPN. Python и `ubus` нужны на OpenWrt; Python уже установлен, если на нём работает Python-прокси.

## Установка из контейнера панели

Сначала проверьте на OpenWrt fingerprint SSH-сервера:

```sh
dropbearkey -y -f /etc/dropbear/dropbear_ed25519_host_key
```

Вывод содержит публичный ключ и его fingerprint; приватный ключ не печатается. Сопоставьте fingerprint с запросом SSH при установке. Не удаляйте `known_hosts` при неожиданном несовпадении.

Затем в Proxmox: `pct enter 101` (замените ID, если контейнер другой). Внутри контейнера под root:

```sh
apt-get update
apt-get install -y openssh-client
cd /opt/home-server-control-panel
git pull --ff-only
python3 deploy/setup-openwrt.py 192.168.10.1
```

Адрес — LAN IP вашего OpenWrt. При первом подключении подтвердите проверенный fingerprint, затем введите пароль root роутера. Пароль читает сам SSH из терминала; он не сохраняется установщиком. Команда требует интерактивной консоли (`pct enter`, а не неинтерактивный `pct exec`).

Установщик:

1. Создаёт отдельный Ed25519-ключ от пользователя `nerv` в `/etc/nerv/ssh` (существующий ключ сохраняется).
2. Устанавливает `/usr/libexec/nerv-status.py` на роутере.
3. Добавляет ключ в `/etc/dropbear/authorized_keys` с фиксированной командой сбора состояния и запретом терминала, port forwarding, agent forwarding и X11. Остальные ключи сохраняются.
4. Копирует подтверждённую запись host key в отдельный `known_hosts` службы.
5. Проверяет SSH под пользователем `nerv`, обновляет `openwrt` в конфиге и перезапускает панель. До обновления конфигурации создаётся `config.json.before-openwrt`.

Используется root-аккаунт Dropbear, но этот конкретный ключ ограничен фиксированной командой. Ограничения опираются на корректную работу Dropbear. Сам сборщик не читает `SSH_ORIGINAL_COMMAND`, не вызывает shell и не выполняет операции изменения системы. Установочный вход root с паролем имеет обычные права администратора и используется только для размещения сборщика/ключа.

Повторный запуск сохраняет ключ, заменяет его запись ограниченной командой и не дублирует ссылку AdGuard. При ошибке установки можно исправить причину и запустить повторно. Не используйте ключ панели для других задач.

## Работа и диагностика

SSH-данные и проверки сети кэшируются на 15 секунд, общих для вкладок. При потере SSH прежние значения служб остаются с подписью и временем последнего успешного сбора; свежие проверки DNS/портов показываются отдельно. Отказ OpenWrt не блокирует метрики Proxmox.

В деморежиме никакие подключения к роутеру не выполняются. В LIVE без блока `openwrt.enabled=true` отображается «не подключён»; устанавливать интеграцию для работы Proxmox не обязательно.

При ошибке:

```sh
systemctl status nerv-panel --no-pager
journalctl -u nerv-panel -n 40 --no-pager
```

SSH stderr не возвращается браузеру: там может оказаться чувствительная информация из окружения/сервера. Проверяйте существование ключей, права доступа пользователя `nerv`, запись host key и наличие Python/ubus на OpenWrt. Не отключайте `StrictHostKeyChecking`.

Чтобы отключить мониторинг, задайте `openwrt.enabled=false` в `/etc/nerv/config.json` и перезапустите службу. Это не останавливает службы роутера. Для полного удаления удалите только строку ключа `nerv-panel-monitor` из `/etc/dropbear/authorized_keys` и `/usr/libexec/nerv-status.py`.
