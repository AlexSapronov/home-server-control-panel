# NERV · Home Server Control Panel

Веб-панель домашней инфраструктуры в стиле NERV / MAGI из [libre_hw_tab](https://github.com/AlexSapronov/libre_hw_tab): угловые панели, сегментные индикаторы, темы NERV, EVA-00, EVA-01 и EVA-02. Русский интерфейс для ПК, планшета и телефона.

Скриншоты desktop/mobile формируются браузерной проверкой в GitHub Actions и доступны в артефакте `nerv-preview`.

## Версия 0.3

- Proxmox API: первый доступный узел, CPU, RAM, uptime.
- VM и LXC по всем доступным узлам, поиск по имени, ID или узлу, фильтры по типу и состоянию. Избранные машины сохраняются в браузере и отображаются первыми. На телефоне список использует карточки.
- Хранилища и последние 20 доступных задач по узлам, включая vzdump.
- История CPU / RAM: последние 60 успешных замеров текущей сессии, опрос раз в 5 секунд. В скрытой вкладке опрос приостановлен.
- Настраиваемые ссылки на сервисы. Отдельный блок OpenWrt: процессы AdGuard, zapret и Telegram-прокси, DNS, порты, WAN и состояние AmneziaWG. [Подключение и ограничения проверок](docs/openwrt.md).
- Явный деморежим и предупреждение об устаревших данных при потере связи.
- Запуск, штатное выключение и перезагрузка выбранных VM и LXC. Панель показывает результат задачи Proxmox.

## Быстрый просмотр

Python 3.11+, внешние библиотеки и сборка интерфейса не нужны.

```sh
git clone https://github.com/AlexSapronov/home-server-control-panel.git
cd home-server-control-panel
cp config.example.json config.json
python3 server.py
```

Открыть http://127.0.0.1:8080. По умолчанию демонстрационные данные; Media-машина и значения ресурсов — примеры. Ссылки из примера относятся к частной локальной сети: замените своими. Без config.json сервер запускается в деморежиме без ссылок.

Windows: `Copy-Item config.example.json config.json`, затем `py server.py`.

## Подключение Proxmox

1. Создайте отдельного пользователя, например `nerv@pve`, и назначьте ему роль `PVEAuditor` на `/` с наследованием.
2. Создайте API-токен с разделением привилегий (`Privilege Separation`) и назначьте токену `PVEAuditor` на `/` с наследованием. Эффективные права токена ограничены правами пользователя. Панель показывает только ресурсы и задачи, доступные этому токену.
3. Безопасно скопируйте с узла `/etc/pve/pve-root-ca.pem` на машину с панелью. В `proxmox.ca_file` укажите локальный путь. Проверяется доверие CA и соответствие имени/IP сертификату. Для публичного доверенного CA удалите `ca_file`. Если IP не входит в SAN, используйте имя из сертификата, доступное через DNS; не отключайте TLS-проверку.
4. В локальном `config.json` смените `mode` на `live`, задайте HTTPS-адрес API и ссылки на сервисы.
5. Передайте секрет через окружение и перезапустите процесс:

```sh
export PROXMOX_TOKEN='nerv@pve!dashboard=REPLACE_WITH_TOKEN_SECRET'
python3 server.py
```

Токен остаётся на Python-сервере и не отправляется браузеру. Конфиг и `.env` исключены из Git. Реальные токены не должны попадать в коммиты или общие журналы.

Панель работает без root в отдельном LXC/VM. Живое подключение к домашнему гипервизору необходимо проверить после установки: из среды разработки доступа к нему нет.

## Управление VM и LXC

1. Задайте `NERV_PASSWORD` в окружении панели и используйте HTTPS при доступе по сети.
2. В `proxmox.managed_vmids` перечислите ID машин, которыми хотите управлять, например `[103]`. Для маршрутизатора OpenWrt и контейнера самой панели исключите их VMID, если хотите сохранить доступ к панели при выключении.
3. В Proxmox создайте роль с единственной привилегией `VM.PowerMgmt`. Добавьте ACL для пользователя и его токена на `/vms/<VMID>` для каждого выбранного ID. Сохраните роль `PVEAuditor` на `/` для мониторинга.
4. Перезапустите панель. В разделе «VM и контейнеры» появятся доступные действия. Выключение выполняется штатно через `shutdown`, перезапуск через `reboot`.

При пустом списке VMID, без пароля или в деморежиме управление недоступно.

## Постоянный запуск

[Пример systemd](deploy/nerv-panel.service) предполагает:

- код в `/opt/home-server-control-panel`, отдельный системный пользователь `nerv`;
- `/etc/nerv/config.json` и при необходимости `/etc/nerv/pve-root-ca.pem`, доступные пользователю `nerv`;
- `/etc/nerv/panel.env` с `PROXMOX_TOKEN=...` и `NERV_PASSWORD=...`; права `0600`, владелец root (systemd читает его до смены пользователя);
- HTTPS reverse proxy перед `127.0.0.1:8080`, доступ только из доверенной LAN/VPN. Сам Python-сервер обслуживает HTTP.

`python3 server.py --host 0.0.0.0 --port 8080` открывает порт на всех интерфейсах. Используйте firewall и HTTPS-прокси; не пробрасывайте порт в интернет. `NERV_PASSWORD` включает Basic Auth для интерфейса и API, имя пользователя `admin`. Пароль при передаче защищён только поверх HTTPS. Без этой переменной панель доступна каждому, кто может подключиться к порту.

Панель умеет управлять списком сайтов через существующий AWG-туннель OpenWrt. Настройки WAN, DHCP и ключи VPN через панель не редактируются. Перенос провайдерского кабеля и импорт AmneziaWG выполняются отдельно.

## Сайты через AWG

В разделе OpenWrt доступен список общих доменных правил AWG: добавление сайта по имени или ссылке и удаление правила. Изменения применяются на роутере для всей сети. Поддомены входят в правило автоматически; для `youtube.com`, `x.com`, `chatgpt.com` добавляются также связанные домены сервиса.

После настройки мониторинга установите отдельный ограниченный ключ управления: `python3 deploy/setup-awg.py` от root внутри контейнера панели. Требуются `NERV_PASSWORD`, режим LIVE, установленный PBR с `awg0`, nftables и интеграция `dnsmasq.nftset`. Подробности — [в инструкции OpenWrt](docs/openwrt.md#управление-сайтами-awg).

Панель читает текущие правила с роутера. Общие доменные правила `awg0` доступны для удаления; правила отдельных устройств, ограничения по портам и прямые WAN-исключения не редактируются этим интерфейсом. Перед применением создаётся резервная копия, при ошибке PBR прежние настройки восстанавливаются. Перезапуск панели не сбрасывает список сайтов.

## Конфигурация

`NERV_CONFIG` переопределяет путь к JSON, по умолчанию — `config.json` рядом с `server.py`. После изменений перезапустите процесс.

| Поле | Назначение |
| --- | --- |
| `mode` | `demo` или `live` |
| `title` | Подпись в шапке |
| `proxmox.url` | HTTPS-адрес Proxmox без `/api2/json` |
| `proxmox.ca_file` | Локальный PEM доверенного CA; необязательно для публичного CA |
| `proxmox.managed_vmids` | Список ID VM и LXC для управления питанием, по умолчанию пустой |
| `services` | Список `{name, url, description}`, только HTTP(S) |

Опрос: `/cluster/resources`, `/nodes/{node}/tasks?limit=20`. CPU/RAM/uptime относятся к первому узлу в ответе API; VM и хранилища — ко всем доступным узлам. Температура и SMART пока не собираются. Мониторинг OpenWrt опционален и подключается отдельно. Успешный vzdump — результат задачи, а не гарантия восстановления; полнота и возраст набора резервных копий пока не проверяются.

## Проверки

```sh
python3 -m unittest discover -s tests -v
node --check static/app.js
```

Тесты: частичный отказ API, отсутствие подмены ошибки пустой «здоровой» панелью, пароль для интерфейса и API, недоступность конфигурации по HTTP и отсутствие секретов в ошибках. Деморежим не проверяет подключение к реальному серверу.
